# Reading Checklist: A Tata Ibadah sidebar row is three lines, ellipsized

**Spec**: `specs/135-tatib-sidebar-row-clamp/spec.md` · **Created**: 2026-10-26 · **Depth**: Standard

- [ ] CHK001 Is "three visual lines" defined so a reader can measure it — three line boxes of the row's own type, not three source lines? [Clarity, Spec §FR-001]
- [ ] CHK002 Does every kind in the request (text, media, passage, song, section break, legacy item) have a requirement that names it? [Completeness, Spec §Requirements]
- [ ] CHK003 Is the fate of the 60-character cut stated for the legacy row's own `…` as well as for the entry labels? [Consistency, Spec §FR-002, §FR-007]
- [ ] CHK004 Are the titled text entry and the legacy row resolved rather than left to the reader? [Clarity, Spec §FR-004, §FR-007, §Clarifications]
- [ ] CHK005 Does the spec say what happens to the `Bait …` line when the heading alone fills the budget? [Coverage, Spec §US2]
- [ ] CHK006 Is the saved copy required to match, and is that requirement traced to the capability's own saved-copy rule? [Consistency, Spec §FR-009]
- [ ] CHK007 Is the filter's behaviour over hidden text stated, so removing the cut does not silently change search? [Coverage, Spec §FR-010]
- [ ] CHK008 Are rows with no hidden text explicitly outside the ellipsis rule, so `…` does not become decoration? [Ambiguity, Spec §SC-002]
- [ ] CHK009 Is each success criterion measurable by observation rather than by opinion? [Measurability, Spec §Success Criteria]
- [ ] CHK010 Does the spec state that the stage pane and the operator dock are out of scope? [Clarity, Spec §Assumptions]
