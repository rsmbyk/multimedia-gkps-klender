Rail fetch feedback — three options

Each page is the real reading shell from spec 243's accepted preview, in dark mode, with a simulated delayed response. Click the actual Search or Media Library rail tile, or the buttons in the top bar. Use the delay buttons to watch the pending state at 0 ms / 1.2 s / 2.5 s; the readout shows computed values. Arrow keys and the links move between options.

  1. Combined — rail lock + reading-page bar + a little placeholder
    The chosen shape: the clicked Search or Media Library tile dims and locks, a 3px bar runs at the top edge of the reading stage, and the stage carries a placeholder built from the destination's own markup — result groups and rows for Search results (or the centred logo and input when Search opens home), intro, filter chips, grouped file rows and cloud/remove controls for Media Library. Both tiles fetch in place, so the rail and sidebars stay usable.
  2. Option A — full-page lock + viewport bar
    The clicked tile dims and locks; a 3px bar runs at the very top of the window for the whole document load. The reading stage keeps whatever it showed. No placeholder.
  3. Option B — in-page parity
    Both rail tiles become in-page fetches through the shell's navigation. The tile locks, a 3px bar runs at the stage's top edge, `aria-busy` is set and a seeded Search / Media Library placeholder appears in the real page layout.
  4. Option C — placeholder only
    Keep today's lock and bar rules untouched (Search has a stage bar; Media Library is still a full page load with a viewport bar) and add only the seeded placeholder while the page is fetched.
